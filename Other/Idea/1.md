# Ngày 1 — Nền tảng dự án, CSDL và kết nối ASP.NET với SQL Server
## 1. Hiểu kiến trúc tổng thể của hệ thống
Mục tiêu của ngày đầu tiên là hiểu được dữ liệu sẽ đi qua hệ thống như thế nào trước khi bắt đầu viết chức năng.
**Kiến trúc cơ bản:**
Người dùng
    ↓
Trình duyệt
    ↓
Giao diện ASP.NET
    ↓
C# xử lý logic
    ↓
SQL Server
    ↓
Database

**Cần hiểu vai trò của từng phần:**
- HTML/CSS/JavaScript: tạo giao diện và các thao tác phía người dùng.
- ASP.NET Web Application: cung cấp cấu trúc để xây dựng website.
- C#: xử lý logic, nhận dữ liệu từ giao diện và làm việc với database.
- SQL Server: lưu trữ dữ liệu.
- Database: chứa các bảng như User, Task, Event,...
Không cần học toàn bộ ASP.NET. Chỉ cần hiểu đủ để biết:
**Người dùng thao tác → C# nhận yêu cầu → C# xử lý → SQL Server đọc/ghi dữ liệu → kết quả quay lại giao diện.**

## 3. Thiết kế Database
Database cần phục vụ trực tiếp các chức năng đã chốt.
### 3.1. Bảng Users
Lưu thông tin người dùng.
Users
├── UserId
├── Username
├── PasswordHash
├── FullName
└── MinimumFreeTime

Ý nghĩa:
- UserId: khóa chính.
- Username: tên đăng nhập.
- PasswordHash: mật khẩu đã mã hóa/lưu dưới dạng hash.
- FullName: tên hiển thị.
- MinimumFreeTime: thời gian Free Time tối thiểu trong ngày, lưu bằng phút.
### 3.2. Bảng Events
Lưu các sự kiện trên Calendar.
Events
├── EventId
├── UserId
├── Title
├── Description
├── StartTime
├── EndTime
└── Color

Trong đó:
- EventId: khóa chính.
- UserId: người sở hữu Event.
- Title: tên Event.
- Description: mô tả.
- StartTime: thời điểm bắt đầu.
- EndTime: thời điểm kết thúc.
- Color: màu hiển thị trên Calendar.
Điều kiện:
EndTime > StartTime

### 3.3. Bảng Tasks
Lưu công việc.
Tasks
├── TaskId
├── UserId
├── Title
├── Description
├── StartTime
├── EndTime
├── Color
└── Status

Các thông tin thời gian tương tự Event.
Status dùng để xác định trạng thái tổng quát của Task, ví dụ:
Pending
InProgress
Completed

### 3.4. Bảng TaskItems
Mỗi Task có nhiều Checklist Item.
TaskItems
├── TaskItemId
├── TaskId
├── Content
├── Weight
└── IsCompleted

Ví dụ Task:
Task: Làm báo cáo

Có:
☑ Viết nội dung       40%
☑ Làm biểu đồ         30%
☐ Kiểm tra lỗi        20%
☐ Hoàn thiện           10%

Nếu hai mục đầu đã hoàn thành:
Progress = 40% + 30%
         = 70%

Weight do người dùng tự nhập.
### 3.5. Bảng Notifications
Dùng cho cảnh báo Free Time.
Notifications
├── NotificationId
├── UserId
├── Title
├── Message
├── CreatedAt
└── IsRead

Ví dụ:
Title:
Free Time không đủ

Message:
Free Time hôm nay chỉ còn 1h20m.
Mức tối thiểu bạn đặt là 2h.

### 4. Quan hệ giữa các bảng
Mối quan hệ chính:
Users
 ├──< Events
 ├──< Tasks
 │      └──< TaskItems
 └──< Notifications

Ý nghĩa:
- Một User có nhiều Event.
- Một User có nhiều Task.
- Một Task có nhiều TaskItem.
- Một User có nhiều Notification.
Cần tạo đầy đủ:
- Primary Key.
- Foreign Key.
- NOT NULL cho dữ liệu bắt buộc.
- UNIQUE cho Username.
- CHECK cho thời gian Event/Task.
### 5. Tạo Database trên SQL Server
Mở SSMS và tạo database cho project.
Ví dụ:
CREATE DATABASE PersonalCalendar;
GO

USE PersonalCalendar;
GO

Sau đó tạo từng bảng theo thiết kế ở trên.
**Thứ tự nên tạo:**
1. Users
2. Events
3. Tasks
4. TaskItems
5. Notifications

Lý do là các bảng sau phụ thuộc Foreign Key vào bảng trước.
6. Kiểm tra Database
Sau khi tạo xong, kiểm tra:
SELECT * FROM Users;
SELECT * FROM Events;
SELECT * FROM Tasks;
SELECT * FROM TaskItems;
SELECT * FROM Notifications;

Ban đầu có thể chưa có dữ liệu.
Nên thêm một User mẫu:
Username: test
FullName: Test User
MinimumFreeTime: 120

120 tương đương:
2 giờ

Sau đó thêm một vài Event và Task mẫu để sau này kiểm tra việc đọc dữ liệu.
## 7. Tạo ASP.NET Web Application
Mở Visual Studio.
Tạo project bằng template ASP.NET Web Application theo framework cũ mà project đang sử dụng.
Không cần chuyển sang ASP.NET Core nếu project hiện tại đang sử dụng framework cũ.
Sau khi tạo project, cần xác định được:
- File giao diện.
- File C# xử lý.
- Web.config.
- Thư mục chứa CSS.
- Thư mục chứa JavaScript.
- Các file .aspx / .cs hoặc cấu trúc tương ứng của template.
Mục tiêu ở bước này không phải hiểu toàn bộ project.
Chỉ cần biết:
File nào hiển thị giao diện và file nào chứa C# xử lý giao diện đó.

## 9. Cấu hình kết nối SQL Server
Trong Web.config, tạo Connection String kết nối tới database.
Ví dụ về cấu trúc:
<connectionStrings>
    <add name="CalendarDB"
         connectionString="..."
         providerName="System.Data.SqlClient" />
</connectionStrings>

Connection String phải phù hợp với SQL Server đang sử dụng.
Ví dụ nếu đang dùng SQL Server Express:
localhost\SQLEXPRESS

Tên Database:
PersonalCalendar

Không cần viết toàn bộ chức năng CRUD ngay lúc này.
Chỉ cần đảm bảo:
ASP.NET
   ↓
C#
   ↓
SQL Server

có thể kết nối được.

## 11. Hiểu cách C# làm việc với Database
Cần nắm được các thành phần cơ bản:
Connection
Command
Reader

Tư duy đơn giản:
Connection
Mở kết nối tới SQL Server.
C# → SQL Server

Command
Gửi câu SQL.
SELECT * FROM Users

Reader
Đọc dữ liệu SQL Server trả về.
UserId
Username
FullName
MinimumFreeTime

Chưa cần học toàn bộ ADO.NET. Chỉ cần hiểu quy trình này để ngày 2 bắt đầu làm CRUD.
