# Ngày 4 — Zoom, Scroll, kiểm thử và hoàn thiện
## 1. Kiểm tra toàn bộ hệ thống trước
Trước khi thêm chức năng mới, chạy lại toàn bộ:
```
Database
ASP.NET
C#

Event
Task
Checklist
Progress
Free Time
Notification
Task Detail
```
Nếu có lỗi chức năng chính thì sửa trước, chưa làm Zoom.
## 2. Scroll dọc Calendar
Calendar phải có thể cuộn theo chiều dọc.
Ví dụ:
06:00
07:00
08:00
...
22:00
23:00

Nếu chiều cao Calendar vượt quá màn hình:
Mouse Wheel
    ↓
Scroll Y

Task Detail Panel không bị cuộn theo Calendar nếu nó thuộc lớp giao diện riêng.
## 3. Scroll ngang Calendar
Calendar có nhiều ngày:
Mon | Tue | Wed | Thu | Fri | Sat | Sun

Nếu không đủ chiều rộng:
Shift + Mouse Wheel
        ↓
Scroll X

Không cần tự viết hệ thống camera.
Có thể tận dụng:
overflow-x

và:
overflow-y

## 4. Thêm Zoom cho Calendar
Quy tắc:
Ctrl + Mouse Wheel
        ↓
Calendar Zoom

Ví dụ:
Zoom 100%
Zoom 110%
Zoom 120%
...

hoặc:
Zoom 100%
Zoom 90%
Zoom 80%
...

Không cần quá nhiều mức.
Chỉ cần giới hạn:
Minimum Zoom
Maximum Zoom

để tránh người dùng zoom quá mức.
## 5. Chỉ Zoom Calendar
Đây là yêu cầu quan trọng.
Khi:
Ctrl + Scroll

thì:
Calendar → thay đổi scale
Task Detail → không thay đổi
Notification → không thay đổi

Ví dụ:
Calendar zoom 150%

Task Detail vẫn giữ:
width = 400px
height = ...

## 6. Xử lý Overflow sau khi Zoom
Khi Calendar zoom lớn:
Calendar width  > container
Calendar height > container

thì xuất hiện:
Scroll X
Scroll Y

Không cần làm hệ thống pan riêng.
Mục tiêu là:
Zoom
 ↓
Content lớn lên
 ↓
Overflow
 ↓
Scroll

## 7. Không triển khai Space + Drag
Không thực hiện chức năng:
Space + Mouse Drag

ở phiên bản hiện tại.
Lý do:
- Không cần thiết cho MVP.
- Có thể gây phức tạp với Scroll.
- Không ảnh hưởng đến chức năng chính.
- Dễ phát sinh lỗi khi kết hợp với Drag Task.
Calendar chỉ cần:
Mouse Wheel       → Vertical Scroll
Shift + Wheel     → Horizontal Scroll
Ctrl + Wheel      → Zoom

## 8. Hoàn thiện Hover Task
Khi đưa chuột lên Task:
Task → nổi bật
Khu vực xung quanh → tối hơn
Cursor → pointer

Khi đưa chuột ra:
Calendar → trở lại bình thường

Không cần animation.
Có thể thực hiện chủ yếu bằng CSS.
## 9. Kiểm thử Event CRUD
Kiểm tra từng trường hợp:
Create
Tạo Event
→ xuất hiện Calendar
→ database có dữ liệu

Update
Sửa Event
→ Calendar thay đổi
→ database thay đổi

Delete
Xóa Event
→ Calendar biến mất
→ database không còn record

## 10. Kiểm thử Task CRUD
Tương tự Event:
Create
Read
Update
Delete

Sau mỗi thao tác kiểm tra cả:
UI
Database

Không chỉ nhìn giao diện mà kết luận đã đúng.
## 11. Kiểm thử Task và Checklist
Tạo một Task:
Task A

Thêm:
Item A → 40%
Item B → 30%
Item C → 20%
Item D → 10%

Test:
Check A → 40%
Check B → 70%
Uncheck A → 30%
Check C → 50%

Đảm bảo vòng tròn Progress luôn đúng.
## 12. Kiểm thử Free Time
Tạo một ngày có nhiều Task:
09:00 → 11:00
13:00 → 15:00
17:00 → 20:00

Sau đó kiểm tra:
Free Time

Tiếp tục tạo thêm Task để làm Free Time giảm xuống dưới mức tối thiểu.
Kiểm tra:
Notification xuất hiện

Sau khoảng 10 giây:
Notification chính biến mất

Indicator vẫn tồn tại nếu đang có cảnh báo.
## 13. Kiểm thử nhiều Panel
Mở:
Task A
Task B
Task C

Sau đó kéo chúng tới các vị trí khác nhau.
Kiểm tra:
- Panel không kéo Calendar.
- Panel không tự đóng.
- Panel không làm mất Panel khác.
- Click Panel A → A lên trên.
- − chỉ thu nhỏ A.
- × chỉ đóng A.
## 14. Kiểm thử Zoom + Panel
Đây là một trường hợp quan trọng.
Mở Task Detail:
Task Detail Panel

Sau đó:
Ctrl + Scroll

Kiểm tra:
Calendar → Zoom
Panel → không Zoom

Sau đó tiếp tục:
Scroll Calendar

Kiểm tra Panel vẫn độc lập.
## 15. Kiểm thử Drag Task + Zoom
Thử:
Zoom 100%
→ Drag Task

Sau đó:
Zoom 150%
→ Drag Task

Kiểm tra thời gian của Task vẫn được xác định chính xác.
Nếu Drag bị lỗi khi Zoom cao, ưu tiên sửa lỗi này trước các phần giao diện khác.
## 16. Kiểm thử dữ liệu không hợp lệ
Cố tình nhập:
Title = rỗng

hoặc:
StartTime > EndTime

hoặc:
StartTime = EndTime

hoặc:
Weight âm

hoặc:
Tổng Weight > 100%

Hệ thống phải từ chối hoặc thông báo lỗi thay vì lưu dữ liệu sai.
## 17. Kiểm tra Database
Sau khi thao tác nhiều lần, kiểm tra trực tiếp SQL Server:
SELECT * FROM Users;
SELECT * FROM Events;
SELECT * FROM Tasks;
SELECT * FROM TaskItems;
SELECT * FROM Notifications;

Kiểm tra:
- Có dữ liệu rác không.
- Có TaskItem mồ côi không.
- Có Event sai thời gian không.
- Có Task sai thời gian không.
- Progress có cần lưu hay tính động không.
Đối với MVP, Progress nên được tính từ TaskItems thay vì lưu riêng, tránh dữ liệu bị lệch.
## 18. Kiểm tra hiệu năng cơ bản
Không cần tối ưu sâu.
Chỉ cần kiểm tra:
- Calendar có bị giật khi scroll không.
- Zoom có bị lag không.
- Mở nhiều Task Panel có quá nặng không.
- Có request Database thừa không.
- Có reload toàn bộ trang sau mỗi thao tác không cần thiết không.
Vì mục tiêu của project là hiệu suất làm việc:
Ưu tiên giao diện phản hồi nhanh hơn hiệu ứng đẹp.
